# Модель угроз root-помощников Live

Root-помощники — единственные места, где сайт AGIOS получает права root:
`web/storage_worker.py` (probe / prepare / revert хранилища превью) и
`web/finalize_worker.py` (превращение проверенного превью в систему на диске).
Сайт вызывает их через `sudo -n /usr/bin/python -B <скрипт>` без аргументов и
передаёт одну строку JSON на stdin; ответ — JSON на stdout.

## Участники и доверие

| Участник | Права | Доверие |
|---|---|---|
| root-помощник | root в Live | доверенный код из squashfs (`/usr/local/share/agi-os/web`, владелец root) |
| сайт `agi-web.service` | системный пользователь `agi-web`, группы `kvm render video disk optical systemd-journal`; sudo только на точные команды (CMP-131) | **не доверенный вызывающий**: запускает QEMU и адаптер входа ChatGPT; `session.json` в `/var/lib/agi-os` он может переписать |
| рабочий стол Live | пользователь `agi` (браузер, терминал), без sudo и без группы `disk` | не доверен; может обращаться к локальному API сайта |
| внутренняя VM превью | root внутри гостя, пишет в образ/раздел превью | не доверена для Live: всё, что лежит в превью, записано гостем |
| модель (провайдер) | только текст через сайт | не доверена; команд не выполняет, конфигурацию проверяет `domain.py` |
| человек у компьютера | физический доступ | доверен: подтверждает целевой диск и разрушительные варианты |

Ценности: данные на всех дисках компьютера, загрузочный носитель Live, root
в Live, пароли пользователя и LUKS (только stdin, см. CMP-134).

## Что проверяют помощники

`storage_worker.py` считает запрос подделанным (операции `probe`, `prepare`,
`revert`, а также `scan`, `adopt`, `remove`, `mark` для продолжения превью после
перезапуска Live, CMP-119):

- **Схема.** Для каждой операции — точный набор ключей, целые числа без `bool`,
  в допустимых пределах, `compression` конечное 1…4, пути устройств по шаблону
  `/dev/[A-Za-z0-9]…`. Любое отклонение — `ValidationError`, а не внутреннее
  исключение (это проверяет фаззинг).
- **Каталоги.** Точки монтирования и резервные копии GPT лежат в
  `/run/agi-os-preview` (root, 0755), а не в каталоге данных сайта. Ключ
  `data_root` из запроса игнорируется. `private_dir` отказывает, если каталог —
  симлинк, принадлежит не root или доступен на запись группе/всем. Файл образа
  создаётся только в обычном каталоге и не поверх симлинка; владелец меняется
  через `chown(..., follow_symlinks=False)`.
- **Вариант хранилища (prepare).** Из запроса берётся только `id`; устройство,
  диск и файловая система заново берутся из `lsblk`:
  `file:` — раздел с ФС из списка, не на целевом диске, не носитель Live, не
  смонтирован; `part:` — диск не только для чтения и не носитель Live, а если это
  целевой диск — он по-прежнему пригоден (`selected_disk`); `shrink:` — только
  раздел NTFS/ext4 целевого GPT-диска; `erase:` — только целевой диск. В тестовой
  VM (маркер fw_cfg) целью может быть только диск `AGIOS_TARGET` — это правило
  теперь применяют и помощники, а не только сайт.
- **Пустой диск.** Диск без таблицы разделов и без сигнатуры считается пустым,
  только если первый МиБ состоит из нулей: зашифрованный без заголовка
  (VeraCrypt, plain dm-crypt) диск не размечается.
- **Монтирование чужих носителей** — всегда `nosuid,nodev,noexec` (probe, файл
  превью, zram): setuid-файл с флешки не даёт `agi` root.
- **Откат (revert).** Запись отката хранит сайт, поэтому она проверяется заново:
  `ram` — только `/dev/zramN` и своя точка монтирования; `file` — только своя
  точка монтирования, раздел с ФС из списка (не носитель Live); удаляются лишь
  `AGIOS-PREVIEW/preview.qcow2`, запись `preview.json` и пустой каталог,
  остальное пользователя остаётся, симлинки не разыменовываются (целевой диск
  при откате не известен, поэтому поддельная запись может указать и на его
  раздел — удалится только этот файл превью); `partition` / `shrink` удаляют только
  раздел с GPT-именем `AGIOS-PREVIEW` на указанном диске, не смонтированный.
  Для `shrink` ужатый раздел должен быть того же диска с тем же номером и ФС,
  а его восстановленная граница — не заходить на другие разделы и не выходить
  за конец диска.
- **Продолжение превью (CMP-119).** `adopt`/`remove` принимают только строковый
  id найденного превью и заново находят его по `lsblk`; откат выводится из
  текущей разметки. `mark` пишет запись только в свободную служебную область
  раздела `AGIOS-PREVIEW` (O_EXCL) или в `AGIOS-PREVIEW/preview.json` на уже
  смонтированном носителе превью. Носители при сканировании монтируются
  `ro` без воспроизведения журнала и `nosuid,nodev,noexec`, образ qcow2 с
  носителя не может ссылаться на backing-файл или внешний data-file.

`finalize_worker.py` дополнительно:

- **Образ превью** — только то, что подготовил `storage_worker`: qcow2 ровно
  по пути `/run/agi-os-preview/ram/preview.qcow2` или
  `/run/agi-os-preview/media/AGIOS-PREVIEW/preview.qcow2` (обычный файл, путь
  без симлинков) либо раздел `AGIOS-PREVIEW`. «Превью на целевом диске»
  определяется по инвентаризации, а не по префиксу строки (раньше `/dev/sdab2`
  считался бы разделом `/dev/sda`).
- Типы полей запроса, пароль LUKS без переводов строк и не длиннее 1024.
- Файловые системы превью монтируются `ro,nosuid,nodev,noexec`.
- Как и раньше: только root, только в Live, отпечаток диска совпадает с
  подтверждённым, конфигурация и запись установки в превью совпадают по дайджесту,
  одно завершение за раз (`flock`).

## Остаточные риски (приняты или переданы)

1. **Группа `disk` у сайта.** `agi-web` может писать в любые блочные
   устройства напрямую, минуя помощников, то есть скомпрометированный сайт
   близок к root по данным дисков. Группа нужна QEMU для сырого раздела превью.
   Будущая работа: убрать `disk`, а помощнику после prepare выдавать `agi-web`
   права только на устройство раздела превью (chown/ACL + правило udev) и
   снимать их при revert.
2. **Локальный API сайта не привязан к пользователю.** Любой процесс рабочего
   стола `agi` (браузер, терминал) может вызвать `127.0.0.1:8787` и через сайт
   запустить root-помощники, включая стирание целевого диска с вводом пути
   подтверждения. Ограничение «только localhost» защищает от сети, не от `agi`.
   Будущая работа: токен сеанса страницы или проверка `SO_PEERCRED`.
3. **sudo (CMP-131).** `agi-web` может выполнять от root ровно
   `/usr/bin/python -B /usr/local/share/agi-os/web/storage_worker.py`,
   `/usr/bin/python -B /usr/local/share/agi-os/web/finalize_worker.py`,
   `pacman -Sy --noconfirm`, `shutdown -h|-r +1` и (только на стенде) чтение
   файла зеркала fw_cfg; у `agi` sudo нет. sudo сбрасывает окружение
   (`env_reset`), так что `PYTHONPATH` и подобные переменные в помощник не
   попадают. Проверки помощников — последняя граница перед root.
4. **Превью исполняется как root в Live.** Завершение делает `arch-chroot` в
   систему превью (`pacman`, `mkinitcpio`, `bootctl`/`grub-install`): её
   программы выполняются от root Live с доступом к `/dev`. Это та же система,
   которая после первой загрузки получит полный доступ к компьютеру, поэтому
   доверие равное; отдельная изоляция (systemd-nspawn без устройств) — будущая
   работа.
5. **Ядро разбирает ФС, записанную гостем.** Монтирование образа превью
   (ro, nosuid, nodev, noexec) остаётся поверхностью атаки на драйвер ФС ядра.
6. **TOCTOU.** Между проверкой по `lsblk` и командой диск может измениться
   (горячее подключение). Для целевого диска окно сужают проверка отпечатка и
   повторное чтение таблицы разделов перед изменением; для других носителей оно
   остаётся.

## Тесты

`web/tests/test_root_helpers.py`: подделанные варианты и записи отката,
симлинки в точках монтирования и в каталоге превью, пустой/непустой диск,
образ вне хранилища, флаги монтирования, и фаззинг — тысячи мутаций корректных
запросов (типы, пути, чужие устройства, лишние/пропущенные ключи) для
`storage_worker` (включая `mark`) и `finalize_worker`: каждая либо отклоняется
`ValidationError`, либо указывает только на разрешённые устройства фикстуры;
`main()` всегда отвечает одной строкой JSON и не запускает команд для
некорректного ввода.
