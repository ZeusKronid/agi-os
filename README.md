# AGIOS

AGIOS загружается с **Live ISO** и открывает сайт `http://localhost:8787`
в Firefox внутри Live-среды. Пользователь обсуждает систему с агентом,
проверяет конфигурацию, а установщик собирает её **в превью**: виртуальная
машина внутри Live показывает готовую систему через **Apache Guacamole** прямо
на сайте. Диск компьютера не меняется, пока пользователь не подтвердит
установку после проверки превью; превью можно убрать и вернуть всё как было.

```text
Компьютер (или внешняя тестовая VM при разработке)
└─ AGIOS Live
   ├─ Firefox → localhost:8787 → агент и контроллер
   ├─ Превью: QEMU + Guacamole → установленная система
   │    хранится в памяти (zram), в файле на любом носителе
   │    или во временном разделе — по выбору, всегда с откатом
   └─ Финализация → диск компьютера (BIOS/UEFI, LUKS, zram-swap)
```

## Сборка

```sh
sudo ./scripts/build-iso.sh          # или --prepare-only и mkarchiso вручную от root
```

Один ISO (`out/agi-os-<дата>-x86_64.iso`, ~2 ГБ) собирается `mkarchiso` из
официальных репозиториев `core`/`extra` с проверкой подписей. В образ
добавляются сайт, клиент Guacamole 1.6.0 из официального исходного релиза и
guacd из закреплённого образа `guacamole/guacd:1.6.0` (squashfs, запускается
через `RootImage=`). Внутренняя VM превью загружает тот же носитель без
графики, поэтому второй образ не нужен. Кэш пакетов хоста и оптимизированные
под конкретный CPU пакеты не используются.

## Работа с системой

1. Загрузить Live ISO. Сайт открывается автоматически.
2. Подключить модель: вход ChatGPT или API-провайдер.
3. Обсудить окружение, приложения и настройки; агент выбирает пакеты из
   Core/Extra и предлагает конфигурацию; приложение проверяет её.
4. «Рассчитать размер и место для превью»: приложение считает точный размер
   системы по данным пакетов и предлагает, где разместить превью:
   - в оперативной памяти (сжатый zram-образ) — диски не затрагиваются;
   - файлом на любом носителе с файловой системой (флешка, второй диск,
     SD-карта) — откат удаляет один файл;
   - новым разделом в неразмеченном месте — откат удаляет одну запись;
   - ужатием NTFS/ext4-раздела целевого диска (сухой прогон, отдельное
     подтверждение) — откат возвращает границу и растит ФС обратно;
   - стиранием диска сейчас — только явно, необратимо.
   Здесь же вводятся пароль пользователя и, по желанию, пароль шифрования
   LUKS2. Ничего из этого не попадает агенту.
5. Дождаться установки: внутренняя VM ставит систему пакетами, чистя кэш между
   партиями, и загружается с готового образа. Проверить систему в браузере.
6. Не подходит — «Вернуть всё как было». Подходит — выключить систему изнутри
   и нажать «Установить на компьютер»: выбрать «рядом с существующими
   данными» или «стереть весь диск», ввести путь диска.
   - Превью в разделе целевого диска: его вложенные разделы становятся
     разделами диска без копирования данных.
   - Превью в памяти или на другом носителе: пофайловое копирование в новые
     разделы с проверкой контрольных сумм.
   Затем пересборка initramfs под реальное железо и регистрация загрузчика.
7. Извлечь носитель и перезагрузить компьютер; в установленной системе
   открывается проверка первого запуска (`agi-os-verify`).

Хранилища: ext4/Btrfs/XFS/F2FS, GPT, GRUB (BIOS/UEFI) или systemd-boot (UEFI),
LUKS2 для корня, swap — zram. Не поддерживаются: сохранение разделов на
MBR-дисках (только стирание), гибернация.

## Проверки и разработка

```sh
python -B -m unittest discover -s tests -v
.local/venv/bin/python -B -m unittest discover -s web/tests -v
node --check web/static/app.js
./scripts/run-live-web-vm.sh [--firmware bios] [--memory 16384]   # внешняя тестовая VM
./scripts/run-live-web-vm.sh --mode disk                          # загрузка установленного диска
```

Общий движок — `archiso/airootfs/usr/local/share/agi-os/installer/`, сайт,
хранилище превью и финализация — `web/`. Отчёты о проверках и снимки экрана
хранятся вне Git и выдаются отдельно.
