# AGIOS

AGIOS загружается с **Live ISO** и открывает сайт `http://localhost:8787`
в Firefox внутри Live-среды. Пользователь обсуждает систему с агентом,
проверяет конфигурацию и запускает сборку. Агент создаёт виртуальный диск,
устанавливает Linux во внутреннюю VM и показывает её экран через
**Apache Guacamole** прямо на сайте. После проверки пользователь выбирает
конечный диск и подтверждает перенос системы из превью.

При разработке сам Live ISO загружается во внешней тестовой VM. Она заменяет
физический компьютер; сайт, контроллер, Guacamole и внутренняя VM работают
внутри Live-среды. Для такого теста нужна вложенная виртуализация KVM.

```text
Компьютер разработчика
└─ Тестовая VM, загруженная с AGIOS Live ISO
   ├─ Firefox → localhost:8787 → агент и контроллер
   ├─ Apache Guacamole → экран внутренней VM
   └─ Внутренняя VM → установленная пользователем система
```

## Сборка и запуск

Для текущего прототипа используется существующий desktop ISO в `out/`, локальный
кэш пакетов QEMU, squashfs-tools, xorriso, bsdtar, uv и доступ к Docker для
получения Guacamole. Пересборка из готового ISO не требует прав root на хосте.

```sh
./scripts/prepare-web.sh
./scripts/run-live-web-vm.sh
```

Результат — `out/agi-os-live-web.iso`. Встроенный `out/agi-os-web.iso`
используется только внутренней VM как установочный носитель. Docker внутри
Live не запускается. Внешняя тестовая VM выделяет 10 ГиБ RAM; внутренняя
по умолчанию получает 4 ГиБ и виртуальный диск 32 ГиБ.

Тестовая консоль доступна по VNC на `127.0.0.1:5997`. Сам сайт работает на
localhost **внутри Live**, поэтому открывать его в браузере хоста не нужно.
`run-installer.sh` и `run-web.sh` запускают ту же внешнюю тестовую VM.

HTML-отчёт со встроенными снимками выдаётся отдельно и не хранится в Git.
Для локальной генерации: `python scripts/web/visual-report.py`.

Подробности: [архитектура и ограничения Live-прототипа](docs/local-web.md).
Текущая сборка использует локальный кэш этой машины и пока не считается
проверенным переносимым релизом для произвольного оборудования.

## Работа с системой

1. Загрузить Live ISO. Сайт открывается автоматически.
2. Подключить модель через настройки: вход ChatGPT или API-провайдер.
3. Обсудить окружение, приложения и настройки; проверить предложение агента.
4. Указать пароль нового пользователя и подтвердить сборку виртуальной системы.
5. Дождаться установки и автоматической загрузки VM с диска без ISO.
6. Проверить систему через встроенный экран Guacamole и выключить её изнутри.
7. Выбрать конечный диск, проверить его данные и ввести путь диска для подтверждения.
8. Дождаться переноса и проверки данных, выключить Live и загрузиться с конечного диска.

В тесте конечный диск — отдельный `.local/live-test-final.qcow2` (40 ГиБ).
После установки `./scripts/run-live-web-vm.sh --mode disk` загружает его без Live ISO.

Внешний тестовый запуск использует существующий мост к модели на хосте.
Он не переносит учётные данные в Live и не переносит туда интерфейс хоста:
сайт и вся оркестрация находятся в Live. Обычная загрузка ISO предлагает
подключить провайдера самостоятельно.

Выбор окружений не ограничен фиксированным списком: агент выбирает пакеты
из Core/Extra. Установщик поддерживает новый диск целиком, GPT,
ext4/Btrfs/XFS/F2FS, GRUB либо systemd-boot. Перенос превью на конечный диск пока поддерживает UEFI + ext4: сохраняет
пароль и пользовательские файлы, расширяет корневой раздел и обновляет загрузчик.
Шифрование, сохранение существующих разделов и экспорт образа пока не реализованы.
Запись конечного диска требует отдельного подтверждения после превью.

Диски VM и история находятся в `/var/lib/agi-os`. В обычном Live-сеансе это
временное хранилище. В тестовом запуске подключается отдельный файл рабочего
диска `.local/live-test-workspace.img`, сохраняющий данные между загрузками.
Пароль новой системы и API-ключи не сохраняются в истории разговора.

Скриншоты — только материал отдельного HTML-отчёта о проверке, функции снимков
экрана в пользовательском интерфейсе нет.

## Проверки и разработка

```sh
python -B -m unittest discover -s tests -v
.local/venv/bin/python -B -m unittest discover -s web/tests -v
node --check web/static/app.js
```

Общий движок находится в `archiso/airootfs/usr/local/share/agi-os/installer/`,
сайт и управление VM — в `web/`. Прежний GTK-клиент сохранён только для
отладки движка: `./scripts/run-native-installer.sh --demo`.
